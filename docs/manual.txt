Flipword Lite v2.0.0 — 极简版（双向）
=================================

这是什么
--------
把原版 Flipword 的核心能力（本地中英词库 + 分词匹配 + 点击看释义）重写成
单文件、零依赖、零网络请求的脚本。v1.5 起支持**双向**：
中文页把词换成英文，英文页把词库里的生僻词换成中文。
控制入口收进插件图标弹窗，设置跨标签页共享，标题/按钮/链接文字也参与替换。
v2.0 起：总开关独立（不再用「0 档」表示关闭），中→英 / 英→中 各有自己的强度和词库，
弹窗用 Vue + Tailwind 重写，源码在 popup/，pnpm build 后由构建脚本打进扩展。

这一版有什么
------------
1. 双向替换：
   · 中文页（中 -> 英）：把词换成英文，强度越高换得越多
   · 英文页（英 -> 中）：把词库里的词换成中文，强度越高换得**越少**。
     额度永远先给生僻词（1 档 ~14%、3 档 ~8%、10 档 ~0.6%），
     最常见的那批词按档位逐步退出替换范围
   正文、标题、按钮、链接文字都会换（V2EX 的文章标题本身就是链接，一样能换）
1b. 方向在弹窗里选：自动（按页面语言判断，推荐）/ 固定 中→英 / 固定 英→中
2. 点击被替换的词 -> 释义卡片：
   英文原词 / 音标 / 释义 / 词根拆解 / 记忆法 / 同根·近义·反义 / 发音（浏览器语音）；
   英→中方向的卡片会标「替换为：xx」。
   （点在链接或按钮上时页面自己处理跳转，不弹卡片——页面功能优先）
3. 18 个词库多选 + 强度 0~10 档，全部在**插件图标的弹窗**里调

怎么装（扩展方式）
------------------
1. 把 zip 解压到一个**固定、不会再移动**的文件夹里。解压后目录里应该直接看到：
   manifest.json、content.js、popup.html、popup.js、banks-meta.js、icon16/32/48/128.png。
2. 浏览器扩展管理 → 从本地安装 / 加载已解压的扩展 → 选**含 manifest.json 的这一层**。
3. 点浏览器工具栏上的 Flipword 图标 → 弹窗里就是全部控制。

怎么用
------
- 图标弹窗 = 唯一入口（360 宽，Vue + Tailwind）：
  · 右上角总开关：关掉 = 整页还原成原文，不再扫描；打开 = 按当前设置重新替换
  · 两个标签页：「中 → 英」和「英 → 中」，各自的强度和词库完全独立，
    打开时自动切到当前页面所在方向
  · 强度 1~10：中→英时越高换得越多；英→中时越高换得越少（1 = 最密）
  · 词库：18 个，四组（基础/进阶/专业/垂直），多选，至少保留一个；两个标签各选各的
  · 本页：实时统计（替换数 / 扫描轮数 / 耗时 / 错误）+「重扫」「还原」按钮
  · 方向：自动（按页面语言判断）/ 固定中→英 / 固定英→中
  · 可选：页面角标纯计数（不可点、不挡操作，默认关）
- 设置存在 chrome.storage.sync：在一个标签页改了档位，**其他已打开的标签页立刻
  跟着重扫**，不用刷新；登录浏览器账号后跨设备同步。
- 油猴版没有图标弹窗，用控制台命令：
  fwLite.level(8) / fwLite.setBanks(['cet4','ielts']) / fwLite.badge(true) /
  fwLite.stats / fwLite.test("中文") / fwLite.rescan() / fwLite.restore()

强度档位说明
------------
中 -> 英（越高换得越多；关闭请用总开关）
  1-2    很淡，每千字 5~8 词
  3-4    轻，每千字 18~28 词（默认 3）
  5-6    中，每千字 35~45 词
  7-8    强，每千字 60~80 词，8 档起同词可复现
  9      很密，每千字 110 词
  10     全量：不设上限、同词可反复出现（长页面分片扫描，不卡主线程）

英 -> 中（越高换得越少；维基 Machine learning 全文 1.6 万词、4 词库实测）
  1      最密，约 14% 的词换成中文（每 7 个词里 1 个中文，读长句基本靠中文兜住）
  2      约 12%
  3      约 8%（默认）
  4      约 6.5%
  5      约 5%
  6      约 3.5%
  7      约 2%
  8      约 1.3%
  9      约 0.9%
  10     最淡，约 0.6%，只偶尔标注一个

  词库越多密度越高（同一档位再乘一个系数）：选 1 个库 x0.95，4 个库 x1.4，
  8 个库 x2.0，18 个库 x2.4（封顶）。想更密：加档位、加词库，两个都行。
  密度是按每个段落自己的词数算的，所以整页从头到尾一样密——不会出现
  「开头换了一堆、往下拉一个中文都没有」。

跳过规则（v1.4 放宽了）
------------------------
- 照样不碰：script/style/代码块/表单控件/可编辑区/隐藏元素/弹窗浮层（登录框等）
- v1.4 起会替换：标题（h1~h6）、按钮、链接文字、导航文字——只改文本，点击行为不变
- 点在链接/按钮上时事件交给页面（跳转/提交照常），不会弹出释义卡片

数据都在本地
------------
词库、释义、词根全部内嵌在 content.js 里，运行时不发任何网络请求。
设置走 chrome.storage.sync（油猴版退回 localStorage，同源标签页间用 storage 事件同步）。

更新记录
--------
2.0.0  弹窗工程化 + 双向独立设置：
       · 总开关独立：0 档不再代表关闭；关掉后整页还原、统计归零，打开按设置重扫
       · 中→英 / 英→中 各自的强度和词库分开存、分开调，弹窗里两个标签切换
         （设置结构改为 {on, dir, zh:{level,banks}, en:{level,banks}}）
       · 旧设置自动迁移：v1.5 的扁平 {level, banks} 会套用到两侧，level 0 变关闭
       · 弹窗改用 Vue 3 + Tailwind，源码 popup/，pnpm build 产物由 build_lite.py 打进扩展
         （vue 只用 runtime，模板预编译，符合扩展 CSP，无 eval）
       · 英→中卡片：词库没有详解时不再显示「这个词条没有详解数据（生僻词或词库精简档）…」
         那段啰嗦解释，上面已有「替换为：xx」
       · 高档位再提密：6~10 档整体上移，10 档 0.63% -> 1.41%（维基实测），
         9/10 档难度门槛放宽到 rank≤3，候选池才喂得饱
1.5.1  英→中「换得太少、还是读不懂」——两个原因都修了：
       · 密度整体拉高 3~4 倍：1 档 4.2% -> 14%，3 档 2.1% -> 8%，10 档 0.12% -> 0.6%
       · 换成**按段落比例**分配，不再用全局额度池。原先后面的段落抢不到额度，
         长页面越往下越稀；现在每段按自己的词数算该换几个，整页均匀
       · 词库数量真正起作用了：原来 4 个库和 18 个库系数都是 1.6（早早就封顶），
         现在 1 库 x0.95 / 4 库 x1.4 / 18 库 x2.4
       · 修掉难度档位方向反了的老 bug：本意是「额度紧张时优先换生僻词」，
         代码写成了降序，实际一直优先换**最常见**的词，于是 base 被当成
         「卑鄙的」换掉（原文 Based on... 变成「卑鄙的 on...」）。现在改为生僻优先，
         并且按档位设了难度上限（1 档只放过最常 20% 的词，10 档只换最难的）
       · 补了 30 条高频动词/名词的错译（embed 栽种->嵌入、discover 看出->发现、
         eliminate ->消除、regularity ->规律、introduce ->引入…）
       · 卡片开着时点到链接/按钮，卡片先收起，链接照常跳转
       · 修版本号没跟着构建走（content.js 里一直显示 1.5.0）
1.5.0  **双向**：英文页把词库里的生僻词换成中文（英 -> 中）。
       · 方向判定：按页面正文里汉字/拉丁字母比例自动判断，也可在弹窗里固定；
         判定结果在页面存活期内固定，不会被替换后的文本带跑
       · 词形变化自动还原（runs/studied/analyzed -> run/study/analyze，
         内嵌 6900 条变形表 + 规则兜底），换的是原形的释义
       · 额度紧张时优先换**生僻**的词（按词频分 10 档难度，0 最常见 9 最生僻）
       · 功能词（the/of/through/that…约 100 个）永不替换，避免句子读不通
       · 弹窗新增方向选择；强度说明随方向切换（英->中：0 关闭、1 最密、10 最淡）
       · 只用词库里的词，不补基础词——已过四六级的话，正文中出现的中文
         基本就是值得记的生词
       · 英文页内存按需加载（中文页完全不解析 2.1 万条反向词典）
1.4.0  入口改造 + 设置共享：
       · 页面内右下角悬浮按钮/面板移除，控制全部收进插件图标弹窗（popup.html）
       · 设置（强度/词库/角标）从「每个网站一份 localStorage」改成 chrome.storage.sync，
         跨标签页实时同步（一个标签页调档位，其它标签页立刻重扫），登录后跨设备同步
       · 豁免放宽：标题、按钮、链接文字也替换（V2EX 文章标题是 <a>，现在也能换）；
         点在链接/按钮上时不抢事件，页面功能不受影响
       · 新增扩展图标（纯标准库绘制）；油猴版无弹窗，沿用控制台命令
1.3.1  选词改回**词频优先**：同一个中文对上多个英文时，取最常用的那个（这是背单词工具，
       不追求翻译准确）。实测 674 条改动的平均词频 5.95 -> 7.48，655 条变得更常用
       （洪水 deluge->flood、山顶 crest->peak、垃圾 litter->junk、处理 deal->handle）。
       只在词频相差 0.5 以内时才看词义是否命中首要释义；另外把最常出现在正文里的
       55 个中文钉成正常译法（领域 province->domain、尝试 stab->attempt、医学 medi->medical、
       方案 project->scheme）。释义卡片顶部新增「替换前：xx」标签，释义没命中原词时也会提示。
       顺带修掉一个隐藏很久的 bug：整页扫描会把 <body> 当成弹窗跳过（维基这类站点会给 body
       加 mwe-popups-* 类名，撞上 modal|popup 规则），导致**调档位/换词库后整页重扫什么都没干**，
       数字一直是 0。现在根节点不做跳过判断，class 兜底也放过 body/html。
       另外整页扫描改成分片执行（每片 40ms），10 档在长页面上不会再卡住主线程。
1.3.0  修复：卡片右上角 × 与 🔊 按钮点不动（事件在捕获阶段被掐断）；连续两个词被替换时
       英文之间没有空格（educationrealm -> education realm）；顺带校正 550 条"次要义项"
       造成的错配（获得|score -> obtain、管理|harness -> management、提供|tender -> provide…）
1.2.0  45 个原词库缺失的基础词（学习/打开/工作…）补齐音标和中文释义，卡片不再空白
1.1.0  加点击看释义、18 个词库多选、0~10 档强度
1.0.0  单文件极简版：零网络、零后台、带角标与统计面板

已知限制
--------
- 英->中方向一个英文词只对应一个中文释义，多义词按最常用义翻
  （match -> 火柴，即便原句是「匹配」的意思）；点卡片能看到完整释义。
- 词库是「中文→英文」反向索引，没收录的中文词不会替换，覆盖率有上限。
- 标题/按钮被换成英文后，原中文就看不到了（想知道原词就点它看卡片，卡片里有「替换前」）。
- 生僻词只带精简释义（音标 + 释义 + 同根），没有词根拆解和记忆法。
- 45 个最常见的基础词（学习/打开/工作/使用…）原词库没有收录，是单独补齐的：
  只有音标 + 中文释义，没有词根拆解、记忆法和近反义（其余 1.3 万条是完整的）。
- 图标弹窗需要支持扩展弹窗的浏览器；油猴版没有弹窗，用控制台命令控制。
