## 正文

```
先说痛点。

我读英文资料的真实状态是：一段话能看懂七成，卡在两三个词上。切到翻译软件、查完、切回来，节奏已经断了。读三行就想放弃。

后来试过"整页翻译"，问题反过来了：中文全在，英文一个不看，读完了也不知道原文长什么样。

所以做了个小工具，思路是中间那条路：**不翻译整页，只替换一部分词**。

- 中文网页 → 按强度把词库里的中文词换成英文。熟悉的语境托着你，生词自然出现在句子里。
- 英文网页 → 把一部分英文词换成中文。卡住的地方一眼就懂，同时保留完整的英文原句和语法。
- 点任意被替换的词 → 音标、中文释义、同根词、近义/反义。点空白关闭。

几个我觉得比较关键的设计：

**1. 强度 1~10，而不是开关**
1 档几乎每句都有替换，10 档只偶尔标注一个。中文页越高换得越多；英文页 1 最密、10 最淡（越淡越适合练阅读）。

**2. 英→中优先换生僻词**
最早版本是平均分配的，结果出现 "Based on the concept" 变成 "卑鄙的 on the concept" —— base 有个罕见义项"卑劣的"，换了比不换更难读。现在按词频分档，越常用的词越晚被替换，10 档只换最难的那批。

**3. 密度按段落算，不是全页抢额度**
原来是"总额度减去已用"，长文章开头换一堆、往下拉一个中文都没有。现在每个段落按自己的词数分配，整页均匀。

**4. 站点黑白名单 + 按站锁语言**
自动判语言偶尔会错（比如中英混排的技术博客）。除了全局「自动/中文页/英文页」，还能只对某个站锁定语言；也可以把某个站加进黑名单，它就不替换了。

**5. 完全离线**
17,000 条中→英词条、21,000 条英→中词条、6,877 条词形变化，全部打包在扩展里。不发任何请求、没有埋点、不要账号。断网也能用，这一点你可以直接验证。

词库 18 个，分四组：基础（四级/六级）、进阶（考研/雅思/托福/GRE）、专业（计算机/医学/法律/经济）、垂直（新闻/科技/商务/学术）。已经过了六级的可以只留进阶和专业。

**已知问题，不藏着**

- 中文一词多义时会选错义项（match 有时给"火柴"）。卡片里会显示替换前的中文，能看出来。这是词频优先的必然代价——我更看重"高频词优先"，而不是"每个词都翻对"。
- 离线词典覆盖面不如在线翻译，专有名词基本不动。
- 图片里的文字、Canvas、部分富文本编辑器不处理。

如果这个思路对你有用，或者你觉得哪儿不对，都欢迎在下面说。特别是"强度与词库怎么配才好读"，我自己调了很多轮，未必是最优解。
```

## 可能被问到的问题（提前想好）

| 问题 | 回答要点 |
|---|---|
| 和 MixRead / Toucan 有什么不同 | 完全离线（它们多依赖 AI/在线翻译）；双向；有站点规则和按站锁语言；开源 |
| 会不会偷数据 | 没有任何网络请求，可以断网验证；权限只有 storage 和全站内容脚本（替换文字必需） |
| 为什么要全站权限 | 功能就是替换任意网页的文字，无法预知用户读哪些站；只处理文本节点 |
| 词库哪来的 | 公开词表整理，已剔除基础功能词；释义人工补了 45 条高频词 |
| 手机上能用吗 | 不支持，扩展只跑桌面浏览器 |
| 能不能加日语/韩语 | 数据不够，做不了；后续可能只做能力内的语言对 |
